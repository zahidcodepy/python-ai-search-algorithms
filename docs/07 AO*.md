# AO* Search

## Experiment Information

- **Programming Language:** Python 3
- **Algorithm:** AO* (Informed Search on AND-OR Graphs)

## Objective

The objective is to understand how a problem that can be broken into sub-problems is represented as an AND-OR graph, and how AO* uses heuristic estimates and cost revision to find the cheapest way to solve it.

## Introduction

Some problems cannot be solved by following a single path. A task may be solved in more than one way (**OR**), and some ways require several sub-tasks to *all* be completed (**AND**). AO* is designed for exactly this kind of problem. Instead of a path, its answer is a **solution graph**: the chosen set of nodes and options that solves the whole problem.

## Theory

- An **AND-OR graph** has two kinds of choices at a node:
  - **OR option** — solve *one* of the alternatives.
  - **AND option** — solve *all* of the listed children.
- Each node has a cost estimate h(n). For leaf (primitive) nodes this is their exact cost; for other nodes it is an **estimate** that may turn out to be wrong.
- The cost of an option is the sum of `edge cost + h(child)` over its children. A node takes the cost of its **cheapest** option.
- AO* works with a **current best partial solution graph**. It expands an unsolved node on that graph, evaluates its options, and then **revises** (back-propagates) the costs of its ancestors.
- Because of this revision, the best option at a node can **change** during the search — an option that looked cheap may become expensive once its children are examined.
- A node is **solved** when the child nodes of its best option are all solved. The search ends when the start node is solved.
- With heuristic estimates that never overestimate the true cost (admissible), AO* finds the optimal solution graph.

## How AO* Works

1. Start with the root node and its estimate.
2. Follow the current best option down the graph to find an unexpanded, unsolved node.
3. Expand it: calculate the cost of each of its options.
4. Keep the cheapest option as its best option and update its cost.
5. Revise the costs of its ancestors, switching their best option if another has become cheaper.
6. Mark nodes as solved when all children of their best option are solved.
7. Repeat until the start node is solved.

## Heuristic Function

h(n) is the estimated cost of solving node `n`. For leaf nodes it is the exact cost.

| Node | Type | h(n) / cost |
|------|------|-------------|
| A | Non-leaf (estimate) | 3 |
| B | Non-leaf (estimate) | 2 |
| C | Non-leaf (estimate) | 1 |
| D | Non-leaf (estimate) | 1 |
| E | Leaf (exact cost) | 4 |
| F | Leaf (exact cost) | 3 |
| G | Leaf (exact cost) | 1 |
| H | Leaf (exact cost) | 2 |

Every edge to a child has a cost of 1.

## Algorithm

1. Mark all leaf nodes as solved. Set the working cost of every node to its estimate.
2. While the start node is not solved:
   1. Trace the current best solution graph from the start node and pick an unexpanded, unsolved node.
   2. Expand it and calculate the cost of every option: sum of (edge cost + h(child)).
   3. Store the cheapest option as the node's best option and set its cost.
   4. Revise the costs and best options of the expanded nodes above it.
   5. Mark a node solved if all children of its best option are solved.
3. Follow the best options from the start node to read off the solution graph and its cost.

## Python Implementation

The full implementation is available at [`../src/ao_star.py`](../src/ao_star.py).

**Key parts of the code:**
- `graph` stores each node as a list of options; an option with one child is an OR choice, an option with several children is an AND choice.
- `option_cost` sums `EDGE_COST + h[child]` over the children of an option.
- `revise` recalculates every expanded node's cost and best option until nothing changes — this is the back-propagation step, and it is what lets the best option switch.
- `find_unexpanded` walks down the current best solution graph to find the next node to expand.
- The loop ends when the start node is in the `solved` set.

## Step-by-Step Execution

| Step | Node expanded | Option costs | Updated h | Best option at A |
|------|---------------|--------------|-----------|------------------|
| 1 | A | via B = 2+1 = 3; via C AND D = (1+1)+(1+1) = 4 | h(A) = 3 | B |
| 2 | B | E AND F = (4+1)+(3+1) = 9 | h(B) = 2 → 9, B solved. A: via B = 10, via C AND D = 4 | **C AND D** (switched) |
| 3 | C | G = 1+1 = 2 | h(C) = 1 → 2, C solved. A: (2+1)+(1+1) = 5 | C AND D |
| 4 | D | H = 2+1 = 3 | h(D) = 1 → 3, D solved. A: (2+1)+(3+1) = 7 | C AND D, A solved |

At step 1, the estimate for B (2) made the OR option via B look cheapest. Expanding B showed its real cost was 9, so the revised cost of A through B became 10, and AO* switched to the AND option (C AND D). The final solution graph is A → (C AND D), C → G, D → H, with a total cost of 7.

## Time Complexity

The running time depends on the structure of the AND-OR graph and on the quality of the heuristic. In this implementation every node is expanded at most once, so there are at most V expansions, and each one is followed by a revision pass over the expanded nodes. A simple upper bound for this teaching implementation is **O(V² · E)**, where V is the number of nodes and E is the number of edges. The size of the AND-OR graph itself can grow exponentially for real problems, so AO* is usually guided by a good heuristic.

## Space Complexity

**O(V)** to store the cost estimates, best options, and the expanded and solved sets for the nodes of the graph.

## Advantages

- Handles problems that can be decomposed into sub-problems (AND arcs), which A* cannot represent.
- Uses heuristic estimates to avoid expanding nodes that are not on a promising solution graph.
- Revises its choices when an estimate turns out to be wrong.
- Finds an optimal solution graph when the heuristic never overestimates.

## Disadvantages

- More complex to implement than A* or Best First Search.
- Needs a good, non-overestimating heuristic for optimal results.
- Cost revision adds extra work after every expansion.
- Standard AO* assumes the graph has no cycles.
- Memory use can be large for big AND-OR graphs.

## Applications

- Problem decomposition and planning
- Game playing and puzzle solving
- Expert systems and diagnosis
- Theorem proving
- Task scheduling with sub-tasks

## AO* vs A*

| Feature | A* | AO* |
|---------|----|-----|
| Graph type | OR graph (ordinary graph) | AND-OR graph |
| Answer | A single path | A solution graph (tree of nodes) |
| Cost of a choice | g(n) + h(n) | Sum of (edge cost + h(child)) over an option |
| Cost revision | Not needed | Back-propagates revised costs to ancestors |
| AND arcs | Not supported | Supported |

## Viva Questions

1. **What is AO* search?**
   It is an informed search algorithm that finds the lowest-cost solution graph in an AND-OR graph.

2. **What is an AND-OR graph?**
   A graph where a node can be solved by one of several alternatives (OR) or by solving several sub-problems together (AND).

3. **What is the difference between an AND arc and an OR arc?**
   An OR arc needs only one child to be solved; an AND arc needs all of its children to be solved.

4. **What is a solution graph?**
   The set of nodes and chosen options that together solve the start node — AO*'s answer, instead of a single path.

5. **What is cost revision (back-propagation) in AO*?**
   After expanding a node, its new cost is passed up to its ancestors, which may then change their best option.

6. **How is the cost of an AND option calculated?**
   By summing (edge cost + cost of the child) over all children of that option.

7. **What is the difference between A* and AO*?**
   A* searches an ordinary graph for a path using g(n) + h(n); AO* searches an AND-OR graph for a solution graph using cost revision.

8. **When is AO* optimal?**
   When the heuristic never overestimates the true cost of a node.

9. **When does AO* stop?**
   When the start node is marked solved.

## Conclusion

AO* was implemented in Python for an AND-OR graph using heuristic estimates and cost revision. The experiment shows how an optimistic estimate can mislead the search at first and how revision corrects it: AO* switched from the option via B to the AND option (C and D) and found a solution graph of total cost 7.
